# Example: Re-simulate existing Transaction

In this example, we'll walk through how to re-simulate a transaction that initially failed due to a problem in the calldata.

**Step 1: Locate and Analyze the Failed Transaction**

To start, open [Walnut](http://app.walnut.dev) and use search to find the transaction with hash: `0x04e9aaf268efe3fd9a328f5d40867231dfae14549126db8ed5471d3b3ed4da78` .

<Screenshot src={ReSimulationAnalyze} alt="Analyze Transaction" />

The transaction has reverted with the following error message: `"Number must be greater than 0"`, originating from `is_positive` function.
The calldata reveals that the function received `0`, which violates the function's requirement for a positive number.

**Step 2: Re-Simulate the Transaction**

<Screenshot src={ReSimulationExample} alt="Re-Simulation Example Form Field" />

To resolve the issue, we modify the calldata by replacing the invalid value `0x0` with a valid positive number, such as `0x5`. This change satisfies the `is_positive` function's requirement. Other parameters remain unchanged because they are correct and unrelated to the error. Focusing only on the problematic value avoids introducing new issues. Click **"Run Simulation"** to execute the transaction with the updated calldata.

**Step 5: Check the Simulation Result**

After running the simulation with the updated calldata, the transaction succeeds. The error is resolved because the modified argument (`0x5`) satisfies the `is_positive` function's requirement. Check the simulation results [link](https://app.walnut.dev/simulations?senderAddress=0x0565f25d19b517d45793b664084d02d5629cdda04e9a57ff44c36b2da157e65f&calldata=0x1%2C0x1d9afc66bb8bf890fd3395e85da7e7173236cb36eb4d33360bc21552d2865e5%2C0xad6422d28af18f3ff5089f6ba5268de9ba155aca3e2e38f5aec314fb140845%2C0x1%2C0x5&transactionVersion=1&blockNumber=395442&chainId=SN_SEPOLIA).
